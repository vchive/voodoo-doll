# 0003 · 环境作为 agent；六个 agent 位；现代穿着的素材甄别

日期：2026-09-18
状态：**用户已确认方向**（本文按此实现）

## 用户的三条要求（原话摘录）

1. 「先定义一下每个角色所拥有的与环境交互的内容」；「环境应该也是一个 agent，环境拥有的
   特性就是当前环境里面的一些物体啥的，不管是巫毒娃娃&&主人公还是其他角色 agent 去跟环境
   交互的时候，环境也应该是有反馈的，这样用 agent 去模拟环境，就会少很多业务逻辑，也能增加趣味性。」
2. 「我们这个场景是现代社会，需要的是各种现代角色的穿着，你直接复用游戏素材的时候需要甄别。」
3. 「默认可以自定义的角色可以无上限，但是先初定 6 个 agent 角色：巫毒娃娃&&玩家角色，环境角色，
   角色A，角色B，角色C，角色Z（通用路人角色），这其中，角色A-C都可以给他们自定义名称。」

## 一、环境 agent 的边界（最重要的一条设计决定）

环境**只能给反馈，不能有意志**。否则它会和人物抢戏，也会让"是我造成的"这种掌控感失焦。

| 环境能做 | 环境不能做 |
| --- | --- |
| 以物件/天气为主语说一句话（"台灯闪了一下，灭了。"） | 替任何人物说话、替人物做决定 |
| 改自己的状态：天气、灯光 | 让人物移动、让人物出场或退场 |
| 触发可见特效：闪烁、敲门声、雨 | 推进剧情、发明新物件 |

环境的输入是「刚刚发生了什么」：玩家说了什么、人物做了什么（尤其是 `use` 动作）。
它的输出限定在**可观察的现象**。

## 二、每个身份与环境交互的内容

不是权限系统，是**性格**。定义在 `shared/environment.js` 的 `ROLE_AFFORDANCES`：

| 身份 | 会对环境做什么 | 为什么 |
| --- | --- | --- |
| 玩家角色（protagonist） | 坐下、躺下、看窗外、关灯、摔手机、开关门、看手机 | 受伤的人的动作向内、带情绪但不外放 |
| A（villain） | 摔门、踢椅子、敲桌、按喇叭、锁门、倒酒 | 攻击性外放，指向物件而不敢指向人 |
| B（rival） | 坐下、看、续杯、打字、开门、拿杯子 | 轻描淡写，动作都很"正常" |
| C（witness） | 看、打字、开门、坐、看手机 | 不站队，动作里没有立场 |
| Z（extra） | 按电梯、开水、按喇叭、打字、打印 | 只做不带情绪的事，不抢戏 |
| 娃娃（doll） | **暗手**：让灯闪、让电话响、让雨下、让打印机卡纸 | 它不是人，不"用"东西，而是让东西自己出问题 |

模型给出的 `use` 不在名单里就丢弃——这条是契约层的硬约束，不靠提示词。

## 三、六个 agent 位

| 位 | 是 agent 吗 | 在舞台上有身体吗 | 可改名 |
| --- | --- | --- | --- |
| 娃娃 && 玩家角色 | 娃娃是；玩家角色（YOU）不是 | YOU 有 | 娃娃可命名，YOU 不可 |
| 环境（ENV） | 是 | 没有身体，寄居在物件和天气里 | 否 |
| A | 是 | 有 | **是** |
| B | 是 | 有 | **是** |
| C | 是 | 有 | **是** |
| Z（路人） | 否（本地模板） | 有，每次换身份 | 否 |

「巫毒娃娃 && 玩家角色」共一个 agent 位，与 [决策 0002](0002-agent-split.md) 一致：
娃娃有"手"，玩家有"嘴"，YOU 只是娃娃手里的身体。

**关于旧存档**：旧版里 `B` 是玩家、`A/C/D/E` 是别人。新版 `B` 变成了"另一个人"。
存档 key 从 `voodoo-hex-v4` 升到 `v5`，旧 `present` 里的 id 直接丢弃回默认，
不做映射——避免把旧玩家的身体误认成新的 B。

**数量上限**：先 6 个；`CAST` 是表驱动的，再加一行就多一个位，服务端与前端都不用改逻辑。

## 四、现代穿着的素材甄别

当前借用的两套角色图集（agent_world 的 lucca / robo）**都是奇幻/科幻风格**：
绿色护目镜头盔、橙色装备、金色机器人。与"现代社会"的设定不符，用户明确要求甄别。

已找到并下载的替代候选：

| 素材 | 许可 | 内容 | 风格判断 |
| --- | --- | --- | --- |
| Office worker sprites（OpenGameArt，Solar Granulation） | **CC-BY 4.0**（须署名） | 4 个上班族，16×16，走路/打字/打印/喝水，附电脑与饮水机 | 现代办公，**符合** |
| Pixel Worker "Fukushima"（OpenGameArt，domsson） | **CC0** | 1 个工人，4 方向，走/工作/倒下，4 种变体（口罩/帽子） | 现代劳动者，可作路人 Z |

甄别标准写进 `CREDITS.md`：**只收现代日常穿着**（衬衫、外套、T 恤、工装），
排除任何头盔、护甲、法袍、机甲、明显的奇幻配色。

## 五、对实现的影响

| 位置 | 改动 |
| --- | --- |
| `shared/cast.js` | 六位制；`YOU/A/B/C/Z` + `doll/ENV` 两个非舞台声音；`agent`/`renameable` 标记 |
| `shared/environment.js`（新） | 物件表、身份→动作表、娃娃暗手、`canUse()` 校验 |
| `shared/script-contract.js` | 新增 `use`（谁对什么做了什么）与 `ambient`（天气/灯光变化）两种动作；`ENV` 成为合法说话者 |
| `server/orchestrator.js` | 人物调用之后追加一次 ENV 调用，输入含人物的 `use` 动作 |
| `server/model.js` | 新增 `callEnvironment()`；人物 prompt 里列出本房间物件与自己被允许的动作 |
| `server/local-station.js` | 无模型时 ENV 的本地反馈（沿用原 extras 的环境音） |
| `server/extras.js` | 改为只负责路人 Z |
| `hex/app.js` | 名字可自定义；ENV 台词单独样式；`use` 演出为走到物件前 + 环境反馈 |
| `hex/stage.js` | 物件位置的特效（闪烁/敲击）；天气与灯光叠层 |

## 六、成本

ENV 是**在人物之后**再调一次（它需要知道人物做了什么），所以一场戏多约 1.3 秒。
换取的是环境反馈不用写 if-else。ENV 调用失败或超时时用本地反馈补位，不阻塞整场戏。

## 已落地的验证（2026-09-18）

- 真实模型（deepseek-chat）下一场三人戏 2.2–3.2 秒：娃娃替玩家身体坐下开口、被点名的人物回应、
  环境对被碰的椅子/窗/酒杯各应一句、天色转夜、路人插话。
- 环境会把多人的动作合成一句观察：三人各拿酒杯 → 「三只酒杯挨个被握住，杯底磕在吧台上，一声轻响」。
- 契约层拒绝：路人摔门、反派看手机（不在其名单）、厨房里关台灯（物件不在房）、环境移动人物、版本 2 旧格式。
- 多人同用一个物件时围在它周围，不再叠格（这是被物件系统逼出来的修复）。

## 未决

- 物件的视觉：家具与物件仍是色块，环境的反馈靠文字 + 物件位置的特效表达。
- Z 路人的变体已按房间固定（走廊/街上戴帽，酒吧戴口罩，其余默认）；将来可按话题换。
- 环境串在人物之后，一场戏比纯人物多约一次调用；若延迟成问题，可改为"先按玩家原话预生成一句环境音、人物结束后再补一句"的两段式。
