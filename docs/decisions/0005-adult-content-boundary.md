# 0005 · 开放世界与成人内容边界

日期：2026-09-18（Asia/Shanghai）
状态：已定方向，代码尚未实现。

## 决定

新增 003 规格，采用“注册表驱动的开放关系世界 + 服务端可控成人表现层”。默认 `contentLevel=sfw`。`mature` 是会话策略，不是客户端布尔参数；它只允许成年虚构角色之间的非露骨暧昧、亲密和成人幽默。

多目标诅咒以稳定的 `targetSetId` 建模，支持 1–4 个成年虚构目标。Pi 只负责受控叙事和角色回应；目标隔离、组合关系、权限、预算、持久化、原子结算和撤回由现有 Node 服务端与 SQLite 掌控。

## 原因

用户希望玩法灵活、可以使用 R18 元素，同时项目要能在手机、微信和自有服务器上稳定运行。让模型自由生成地图、人物或成人内容会破坏存档一致性、隐私隔离、渠道适配和离线回退。将世界状态和内容策略放到服务端注册表与 gate 中，可以保留创作空间，也能在不信任模型输出的情况下验收。

## 永久拒绝项

未成年人或疑似未成年人、性暴力/强迫、图形化性行为、裸露生成、真实人物定向色情/羞辱、现实跟踪或伤害计划。它们必须在输入、草稿和最终 beats 三层拒绝或改写为 SFW，不进入记忆或普通日志。

## 后果

- 002 不宣称实现开放世界或 R18；新工作由 003 任务表接手。
- 成人模式不获得额外 agent 工具权限，不改变 CAS、隐私、取消和离线回退。
- 战报和分享永远 SFW，渠道策略可以强制所有会话回退 SFW。
- 多目标仪式不提供现实中的联系人、定位或投递入口；“同时处理两个人”只发生在注册舞台内，并以关系边和可观察后果表达。
- 年龄确认不是身份证明，也不替代上线前的地区、微信和应用商店合规审核。

## 未决事项

年龄确认交互、地区策略来源、mature 的具体文案强度、审计保留期和正式上线渠道仍需产品与合规确认；在这些事项明确前，只实现 SFW 注册表和 gate。
