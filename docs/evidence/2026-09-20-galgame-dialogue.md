# 2026-09-20 · Galgame 对话窗验收

对应 `MW-30 / SP-15 / MW-AC-30`，依赖已实现的 MW-28/29。用户提供参考图，要求提示像 Galgame 一样显示人物名、说话或思考。此次参考其对话窗组织方式，没有使用参考图的角色或美术资产。

## 实现

- 像素场景放到主要阅读区上方，半透明深蓝对话窗与独立名字牌贴在场景下缘。分别显示角色对白、主角心声、环境旁白；点击对话窗或“下一句”继续，聚焦时 Enter/Space 同效。
- 现有五章每步增加 4–5 句原创演出，三个结局各 4 句。后端 `guidance.dialogueId` 与 `dialogue[{speakerId,kind,text}]` 提供公开展示数据，旧 `passage` 保留兼容。NPC 不公开私密心声，`thought` 仅归 YOU；异地提示不伪造远处 NPC 正在交谈。
- 读完本段后展开推荐动作；“先行动”、地图和自由输入可提前进入行动。预览、确认、取消仍走原来的服务端路径。阅读不会额外结算行动时间，也不暂停世界自然时间。
- 支持上一句、回看本段（到当前阅读位置）、折叠行动记录。阅读位置单独保存在本机，按 world、段落与地点隔离；不会代替世界章节权威。
- 已确认行动反馈和普通人物回应也进入对话窗。章节事件中的旧整段旁白不重复播放；已知脚本人物回应改为纯台词，动作由结构化旁白呈现。
- 离线移动只显示本机反馈，不播放上一个地点缓存的 NPC 台词。320 宽度的自动滚动为名字牌预留顶部空间。

## MW-31 行动记录诊断与服务端回归

用户提供的行动记录中三次“去开门”是真实的历史确认事件，每次均推进了 2 分钟；不是前端重复渲染。旧版本确认后章节指针没有同步，造成玩家已经到达地铁站而章节仍显示客厅开门目标。

本轮保留这些历史事件和原始输入，不删除、不改写、不补发便笺或告示，也不重演对白、不重开已经错过的时间窗口。服务端在生命周期检查时根据已确认事实把章节指针纠偏到当前可继续步骤，并写入一次 `chapter_reconciled` 审计事件；重复检查幂等且不推进时间。当前真实存档已纠偏为：地铁站、第二章、目标为打开地铁站玻璃门查看告示，周野在场。

新增 4 组 Python 回归覆盖：非线性教程顺序、纠偏审计幂等、周野作为唯一在场对象的短句接话，以及多对象/离场对象的拒绝与重新选择。`说什么`、`什么意思`、`然后呢`、`继续说` 等短句只在唯一同场角色或已有有效交谈对象时自动关联；多人同场要求明确对象，原对象离场后不会继续调用该角色。未知行动仍保留原文并拒绝，不降级为聊天。

前端行动记录回归还覆盖了三件容易混淆的情况：同一 `eventId` 的确认/回放只保留一条成功记录；未知输入固定保留“你 · 未执行”和“巫柜 · 提示”两条记录，并可从错误面板直接恢复到推荐动作；失败输入不会推进本地时钟、地点、章节或世界版本。导入存档或切换 `worldId` 时会清理旧世界的本机日志、对白游标和教程状态，旧的无 `eventId` 日志仍按兼容规则保留。

行动记录审计补充：未知输入（例如“巫柜”）每次只追加两条本地记录：`你 · 未执行`（保留原文）与`巫柜 · 提示`（保留恢复说明）。`renderSnapshot`/`updateLog` 只重绘已有记录，不追加副本；刷新后旧日志仍可由兼容解析恢复。失败输入不创建 pending、不写成功世界事件、不推进时钟、地点或章节。用户看到的三次“去开门”是历史上三次确认成功的真实行动，每次推进 2 分钟，并非日志重复渲染。后续修复已为新记录补上“第 N 天 HH:MM · 地点”和`已执行/未执行/提示`状态；玩家确认使用 turn/event id 去重，服务端回放中的 `YOU` 事件不会再被当作第二条反馈。旧日志仍保持稀疏格式，不人为补造历史上下文；行动记录仍是本机展示/恢复数据，服务端快照与事件才是权威。

本节仅记录服务端和自动化证据。由于当前 Codex 浏览器连接受宿主锁定及认证限制，本轮没有新增浏览器点击、微信真机或公网证据；这些边界仍保持待测。
