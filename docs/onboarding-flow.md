# 开场流程：故事驱动的人名生成

日期：2026-09-17
状态：**已实现**

## 用户体验

新的开场流程用三个步骤替代了原来的"先给娃娃起名，再手动给角色起名"：

### 第一步：给娃娃起名 + 讲故事

表单包含两个输入：
- **娃娃的名字**（1-12 字，比如"阿布""小黑"）
- **你的故事**（10-600 字，讲述谁伤害了你，发生了什么）

提交后调用 `POST /api/extract-names`，服务端从故事里自动识别人名。

### 第二步：确认人名

娃娃说："好。我叫{娃娃名}。我从你的故事里听到了这些人。名字对吗？"

展示三行输入框，对应 A/B/C 三个角色位：
- 已填入服务端提取的人名
- 玩家可以逐个修改或留空（不需要的人物）
- 提示"确认后就不能再改名了"

### 第三步：人名锁定，演出开始

玩家确认后：
- `onboardingPhase` 置为 `'names-confirmed'`
- 有名字的人物自动加入场上（`state.stage.present`）
- 娃娃说："好。以后他们就是这些名字。你想让我做什么，说给我听就行。"

**关键约束**：演出开始后（`nights > 0`），`applyStaging` 中的改名逻辑不再生效。玩家说"他叫老张"不会再触发改名，避免后续混淆。

## 技术实现

### 状态字段

```javascript
{
  dollName: '',           // 娃娃的名字
  onboardingPhase: null,  // null | 'story-told' | 'names-confirmed'
  story: '',              // 玩家讲的故事（只在 onboarding 阶段保留，确认后清空）
  names: { A: '老张', B: '小周', C: '' },
  nights: 0,              // 演出开始后 > 0
  // ...
}
```

### 服务端端点

`POST /api/extract-names`

请求体：
```json
{
  "story": "我和老张在一起三年了，上个月发现他背着我和小周好上了..."
}
```

响应：
```json
{
  "ok": true,
  "source": "model",  // 或 "local"（模型不可用时的本地回退）
  "names": {
    "A": "老张",
    "B": "小周",
    "C": ""
  }
}
```

#### 模型提示

`extractNames(story)` 调用模型时的提示：

- 识别出最多三个关键人物，按重要性排序（A 最核心，B 第二，C 第三）
- 优先用故事里出现的真实称呼（名字、昵称、关系词如"老张""小周""我妈"）
- 如果故事里没有明确人名，就留空
- 不编造人名，不用代词（他/她），不用角色描述（"那个同事"）
- 每个人名 1-12 字，过滤危险字符

#### 本地回退

模型不可用时，从故事里粗提人名：
- 中文：正则匹配 2-4 字的中文词（在标点前或行尾）
- 英文：首字母大写的词（2-12 字母）
- 最多取前 3 个

### 前端流程

[hex/app.js:520-605](hex/app.js:520-605) `renderOnboarding()`

1. **第一次进入**（`!state.dollName || !state.story`）
   - 渲染表单：娃娃名 input + 故事 textarea
   - 提交时：调用 `/api/extract-names`，拿到 `names` 后存入 `state.names`
   - `onboardingPhase` 置为 `'story-told'`，重新渲染

2. **第二次进入**（`onboardingPhase === 'story-told'`）
   - 渲染人名确认表单：三行 input（A/B/C），预填提取的人名
   - 提交时：收集最终人名，有名字的人加入 `state.stage.present`
   - `onboardingPhase` 置为 `'names-confirmed'`，`story` 清空
   - 隐藏开场 UI，显示娃娃的开场台词

3. **已完成**（`onboardingPhase === 'names-confirmed'`）
   - 跳过开场 UI，直接进入对话界面

### 改名锁定

[hex/app.js:462-478](hex/app.js:462-478) `applyStaging()` 中的改名逻辑外包一层条件：

```javascript
if (state.nights === 0) {
  // 改名逻辑：匹配"他叫老张"等模式
}
```

演出开始后（`nights > 0`），改名逻辑不再执行。

## 设计目标

1. **降低认知负担**：玩家不需要事先想好三个人物的名字，讲故事时自然会提到人名
2. **提高代入感**：从"你的故事"开始，而不是从"起名"开始
3. **避免后续混淆**：演出开始后锁定人名，玩家不会意外改掉角色名字导致记忆混乱
4. **保留灵活性**：确认阶段允许修改，处理提取错误或玩家想用化名的情况

## 未来改进

- 提取质量：当前正则 + 启发式在复杂故事里可能漏掉人名或提错，可以用更强的 NER 模型
- 关系推断：可以尝试从故事里推断 A/B/C 的 archetype（villain / rival / witness）
- 多语言：当前中英混合，其他语言需要调整正则
