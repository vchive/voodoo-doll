# 开场流程验证记录

日期：2026-09-17

## 实现的功能

三步开场流程：
1. 玩家给娃娃起名 + 讲故事
2. 服务端自动提取人名，玩家确认
3. 人名锁定，演出开始

## 实际测试

### 测试用例

- **娃娃名**：小黑
- **故事**：我和老张在一起三年了，上个月发现他背着我和小周好上了。昨天在咖啡厅碰到他们俩，老张连招呼都不打。

### 第一步：故事输入

表单包含：
- 娃娃名输入框（maxlength 12）
- 故事输入框（textarea，maxlength 600）
- 提示："别填真名。它只需要一个你叫得出口的称呼。故事里的人名也可以是化名。"

提交后调用 `POST /api/extract-names`

### 第二步：人名确认

服务端返回提取的人名。

**初始正则问题**：
- 本地回退的正则 `/[一-龥]{2,4}(?=[，。！？、：；""''（）]|$)/g` 匹配了标点前的任意 2-4 字中文词
- 实际提取结果：`起三年了`、`周好上了`、`到他们俩`（都是句子片段，不是人名）

**改进后的正则**（[server/index.js:42-53](server/index.js:42-53)）：
```javascript
// 优先匹配"和XX""跟XX""与XX"结构
const withMatches = story.match(/[和跟与]([一-龥]{2,4})(?=[，。！？、：；在""''（）\s]|$)/g) || [];
const names1 = withMatches.map(m => m.slice(1)).filter(n => n.length >= 2);

// 再匹配标点前的2-4字中文词（兜底）
const punctMatches = story.match(/([一-龥]{2,4})(?=[，。！？、：；""''（）])/g) || [];
```

改进后应该能正确提取"老张"（和老张）和"小周"（和小周）。

**UI 表现**：
- 三行输入框，对应 A/B/C
- 标签：他 / 她 / 知情的人
- 预填提取的人名
- 玩家可以逐个修改或留空
- 提示："确认后就不能再改名了。"

手动修正为：
- A: 老张
- B: 小周
- C: （留空）

### 第三步：演出准备

确认后：
- `onboardingPhase` 置为 `'names-confirmed'`
- `story` 清空
- 有名字的人加入 `state.stage.present`：`['YOU', 'A', 'B']`
- 场上角色显示：你、老张、小周

娃娃开场白："好。以后他们就是这些名字。你想让我做什么，说给我听就行。"

### 待验证

2. **改名锁定生效** - 演出开始后（nights > 0），尝试说"他叫李四"，验证改名逻辑不再执行
3. **改进后的正则** - 清空 localStorage 重新开始，验证"老张""小周"能被正确提取

## 发现的问题

### 1. 本地回退正则太宽泛

**问题**：`/[一-龥]{2,4}(?=[，。！？、：；""''（）]|$)/g` 会匹配"起三年了"这种句子片段。

**原因**：没有考虑语境，只要是标点前的 2-4 字中文词就匹配。

**解决**：
- 优先匹配"和XX"/"跟XX"/"与XX"结构（这些后面通常是人名）
- 兜底才用标点前匹配
- 过滤掉明显不是人名的候选（未来可以加停用词表）

### 2. CSS 样式缺失

**问题**：`.boot-textarea`、`.boot-name-row` 等样式一开始没有定义。

**解决**：在 [hex/styles.css:529-580](hex/styles.css:529-580) 添加了完整的样式定义。

## 改名锁测试

在 `onboardingPhase = 'names-confirmed'` 且 `nights = 0` 的状态下，发送消息："他叫李四"

**预期行为**：
- 如果锁基于 `nights > 0`：改名应该成功（因为 nights 仍为 0）
- 如果锁基于 `onboardingPhase = 'names-confirmed'`：改名应该被拒绝

**实际结果**（待验证）：
- 需要检查 `state.names.A` 是否从"老张"变成"李四"
- 娃娃的回应文本显示："好，以后他就叫李四。"
- 这表明改名逻辑**可能没有被正确阻止**

## 发现的问题汇总

### 1. 本地回退正则太宽泛

**问题**：`/[一-龥]{2,4}(?=[，。！？、：；""''（）]|$)/g` 会匹配"起三年了"这种句子片段。

**原因**：没有考虑语境，只要是标点前的 2-4 字中文词就匹配。

**解决**：
- 优先匹配"和XX"/"跟XX"/"与XX"结构（这些后面通常是人名）
- 兜底才用标点前匹配
- 过滤掉明显不是人名的候选（未来可以加停用词表）

### 2. 演出确认逻辑问题

**问题**：点击选项按钮后，娃娃应该进入"就这样，动手"确认阶段，但实际上陷入了重复澄清的循环。

**可能原因**：
- 本地回退脚本 (`writeScript` 函数) 的状态机逻辑有 bug
- 选项点击后的 `handlePlayerText` 处理不正确
- 需要检查 [hex/doll.js](hex/doll.js) 和 [hex/app.js](hex/app.js) 的演出触发逻辑

### 3. 改名锁可能未生效

**问题**：`onboardingPhase = 'names-confirmed'` 之后，理论上应该禁止改名，但娃娃仍然响应了"他叫李四"的改名请求。

**需要验证**：
- 检查改名逻辑在哪里 ([hex/app.js](hex/app.js) 的 `handlePlayerText` 或 [hex/doll.js](hex/doll.js))
- 确认锁的判断条件是 `nights > 0` 还是 `onboardingPhase !== null`
- 如果是前者，那么当前行为是正确的（因为 nights = 0）
