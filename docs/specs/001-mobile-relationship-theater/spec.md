# 001 · 手机关系剧场

状态：SDD 交接规格，待实现。产品方向已确认；标记为“默认方案”的数值/机制可在实现时根据证据调整，并同步任务与验收。

## 目标与优先级

做一个微信链接可进入的手机 H5 解压游戏。玩家创建多个娃娃，把关系放进小剧场，用手势完成荒诞的组合仪式，再把结果留下作为摆件。

- P0：多人物、双人关系仪式、摆件、手机触控、可部署的普通网页。
- P1：可选 Agent 编剧与服务端保护，性能与易用性优化。
- P2：高级外观、更多配件/服装与视觉精修。

用户已确认：手机/微信、IP+端口发布、可提供服务器、先无后端、玩法与摆件优先、接受双娃娃关系玩法方向。下列容量/成本/手势等为可执行的默认方案，并非用户逐项指定。

## 范围

本轮：每个本地档案最多 4 只娃娃，同场仪式恰好 2 只；至少保留当前单娃娃玩法。先实现三个组合仪式及其摆件结果。关系内容仅属于玩家设备中的游戏小剧场。

不在本轮：多人联网、账户体系/云存档、支付、排行榜、公开发布真人资料、微信登录、小程序、自动向任何人发送消息。无需为 H5 普通链接引入微信 JS-SDK；自定义微信分享卡片另行立项。

真实大模型属于后续可选阶段；供应商未定不阻塞 P0 完成。

## 用户旅程

1. 在微信收到游戏首页链接，打开后看到可直接操作的初始娃娃。
2. 新建第二只，分别设置外号/可选头像；选择两只同场，设置关系类型。
3. 选择「甩锅回旋镖 / 谎话打结 / 烂缘打包」，看到参与者和本轮法力成本。
4. 根据屏幕提示操作，收到即时反馈；完成后才结算法力与结果。
5. 看短剧情，选择再来一次、返回祭坛或把结果作为摆件。
6. 下次从同一浏览器来源打开，恢复娃娃、关系和最近摆件状态。

## 三个组合仪式（默认方案）

| ID | 操作与即时反馈 | 结局 / 摆件状态 |
| --- | --- | --- |
| blame-loop | 交替点击 A/B 的“甩回去”触区共 6 次；重复点击同一侧只给提示，不加进度；每次锅沿关系线弹到另一侧 | 两只娃娃各顶一个锅，旁白“责任循环系统已闭合” / `pot-pair` |
| lie-knot | 长按线结累计 3 秒；松开暂停；线逐渐收紧，身体同步摇晃；支持键盘等价操作 | 线变成可见的结，台词互相对不上 / `knotted` |
| pack-away | 先点击“放进盒子”，再沿 ≥100 CSS px 的封条区域横向划过；同时提供“按住封箱”3 秒替代 | 盒子合拢、盖章“请内部消化”，完成弹跳动画 / `boxed` |

单次流程目标 30–90 秒，输入阶段不能被纯等待占满。动画可以跳过/减少，但完成条件一致。

可以直接重玩同一人物对；开启新仪式时显示中性舞台预览，取消保留上次完成结果，完成后才覆盖。关系类型与视觉结果分开保存（`背叛`不因封箱变成另一种类型）。

## 列表与删除

娃娃列表显示名字、可选头像和当前选中状态。添加与编辑均应有明确入口；达到 4 只时可继续编辑已有角色，但不能添加第 5 只。**P0 暂不提供删除角色**，避免引入撤销/关联关系恢复这一额外流程；不得出现无响应的删除入口。删除与恢复可独立追加规格。载入异常存档时仍必须修复悬空关系/选中引用，且至少保留一只娃娃。

## 非功能要求

| ID | 要求 |
| --- | --- |
| NFR-01 | 核心触区至少 44 × 44 CSS px，正文原则上 ≥12 px，输入字体 ≥16 px；焦点可见、减少动态偏好有效；操作失败有文字反馈 |
| NFR-02 | 手势按下首个可见反馈目标 ≤100 ms；拖动/粒子不等待网络；短帧动画避免布局抖动；首屏关键资源目标 gzip 合计 ≤250 KiB（不含用户头像） |
| NFR-03 | Google Fonts/第三方 CDN 不得是可玩前提；P0 关键资源同源；断开模型服务仍可玩。P0 不承诺首次断网离线加载网页 |
| NFR-04 | 微信不支持/拒绝全屏、传感器、震动、常亮时仍可用触控和页面内摆件完成流程；不反复请求被拒绝权限 |
| NFR-05 | 用户文本仅作为文本渲染；图片限制类型/尺寸，存储失败保留当前会话可用性；部署目录不暴露源码、密钥或任意服务器文件 |
| NFR-06 | 每个实现任务须可追踪到需求和验收；模拟器验证与真机验证分开报告，不以构建通过替代行为验收 |
