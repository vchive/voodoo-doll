## 并行约定

可以并行：T01 状态模型、T08 部署包；接口确定后，T03 舞台与 T04 引擎可并行；T06 可先按结果协议开发再集成。

不能并行写同一个入口/全局样式：`app.js`、`index.html`、`styles.css`、`package.json`、`package-lock.json` 默认由集成负责人统一修改。其他 agent 使用新模块/独立样式并交付连接说明；需要修改共享文件时先明确当前 owner，避免覆盖。

未有 Git 提交时不能假设 `git worktree add` 或分支隔离已可使用。T00 处理基线后再做隔离；相同 workspace 的多个 agent 仍共享文件。

## 每项任务的 SDD 闭环

1. **读规格**：登记 ID、需求/验收映射、输入输出和依赖。
2. **写变更**：调整行为默认值时同步 spec/plan，简述原因，保留用户原始优先级。
3. **实现**：只做本任务必要改动，保留单娃娃存档与现有玩法。
4. **验证**：执行适当的纯状态测试、DOM/浏览器交互或真实 HTTP 测试；不写只复述代码的测试。
5. **记录**：在 acceptance 记录命令/设备/结果/局限，完成定义全部满足再勾选。
6. **交接**：更新 HANDOFF 的现状、待办、运行方式、部署版本与回滚点，不把设计写成事实。
