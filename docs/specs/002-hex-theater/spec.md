## 一句话

**你讲故事，娃娃搭台，你布场，它替你动手。**

巫毒娃娃不是旁白，是同谋。它听你说完发生过的事，把故事搭成一个可以走进去的小小舞台，等你摆好位置，然后它去演那场报复。

## 为什么这么做

001 把"爽"放在动作层（拖拽、连点、长按），爽感随重复衰减。002 把"爽"放在叙事层：**你讲的故事决定了它怎么搭台，你摆的位置决定了它怎么动手**，所以每次的因果链都不一样。

更关键的是角色分工。玩家在这段真实的关系里是失控的一方，没有话语权。002 给玩家的不是更强的点击，而是**叙述权**：你是唯一知道完整故事的人，娃娃是唯一认真听的人，也只有它能去把这件事演出来。玩家从"被讲述的对象"变成"讲述者"。

## 形态：上帝视角的像素小房间

不是"电子蛐蛐"。蛐蛐是被观赏的宠物，玩家在外面看；这个游戏的核心是**叙述权**——玩家是唯一知道完整故事的人。所以位置关系要反过来：**玩家是俯身看进一个盒子的人，盒子里的人不知道你在看。**

- **视角**：全局俯视，一个像素小房间（娃娃屋的平面版）。
- **角色**：像素小人是故事里的角色，主角必须在场景内且有位置与状态。玩家不是从外面看反派倒霉——如果主角不在场，游戏就变成看别人受苦，玩家获得快感但没被安置进这场戏。
- **娃娃本体也在房间里**，是桌上那个亮着的巫毒娃娃。它是玩家能伸进这个世界的唯一一只手：所有对房间的干预都通过它发生。
- **界面比例**：房间占主要视野，娃娃与状态栏在下方边缘，不遮挡场景。

## 场景由内置元件拼接，不自由生成

内置一套可拼接的像素场景元件（房间、家具、天气、站位锚点、关系线渲染），创作层负责**组装与写台词**，不负责凭空生成视觉。

理由：创作层擅长台词与氛围，不擅长凭空捏一个视觉上成立的房间，让它自由发挥会得到一堆对不上的布景。元件化的三个好处——视觉稳定、无网络可跑、上层不可用时体验不塌。

## 核心循环

```text
讲述 → 澄清 → 造景 → 预演 → 确认 → 报复 → 写进娃娃的记忆 → 下一次造景
```

| 阶段 | 玩家做什么 | 娃娃做什么 |
| --- | --- | --- |
| 讲述 | 说发生过的事，一段一段地讲 | 听，记住人和事 |
| 澄清 | 回答关于场景的细节提问，或跳过 | **只问感官细节**：白天还是晚上、有没有下雨、房间里有什么、他在做什么、门开着还是关着 |
| 造景 | 确认它听成了什么，补充或纠正 | 组装内置元件，搭出房间与站位：谁在哪、什么场景、哪句话该出现 |
| 预演 | 看一小段，然后回答"是不是这样" | 先演一小段，主动问玩家这是不是当时的样子 |
| 布场 | 拖动角色位置、选择要点燃的节点 | 提示哪里可以下手，但不替玩家决定 |
| 报复 | 按下动手，看它演出后果 | 执行，演出，并把结果记下来 |

**澄清只问感官细节，不问情节。** 情节玩家已经痛过了，再问一遍等于让玩家复述伤口；细节玩家说得出口，而且细节才是让那个房间变成"真的发生过的地方"的东西。娃娃像在做笔录，不像在做心理访谈。这一步必须可以跳过——不想细说就直接进预演，代价是娃娃记忆浅一点、后面的戏没那么贴。这个取舍是诚实的，不用藏。

**预演是让娃娃可能出错的一步。** 没有预演，娃娃只是个翻译器，转错玩家也看不出来。有了预演，玩家可以说"不对，他那时候不是站着的"，娃娃被纠正，玩家修正，真正的记忆累积从这里开始。预演也是把娃娃从工具变成角色的关键。

循环的闭合点是**记忆**。娃娃造景用的素材全部来自你的讲述，所以讲得越多，下一场戏越贴着你。它久了比你还熟这段故事。

## 造景的真实性约束（重要）

娃娃造景本质上是一次**解释**：它决定了谁站在哪、谁欠谁、哪句话值得被复述。这是这个玩法最有力量的地方，也是最需要约束的地方。

- 娃娃可以夸张风格、可以荒诞化、可以加它自己编的台词。
- **娃娃不得发明玩家没讲过的事实**：不新增角色、不编造没发生过的伤害、不替玩家给某人安上动机并当成事实呈现。
- 造景完成后有一道 **「它听成了这样」** 确认步骤。玩家可以逐条改，改动作为更正的讲述写回娃娃的记忆，并在后续造景中体现。

没有这一条，玩几天之后玩家记住的会是娃娃编的版本。这是产品伦理问题，不是细节。

## 情绪弧线（三层，非可选）

| 层 | 玩家需求 | 游戏给什么 | 报复的形态 |
| --- | --- | --- | --- |
| 一 · 恨 | 出气 | 看他倒霉，且原因是你安排的 | 直接、外显、夸张（失声、打翻、出丑） |
| 二 · 揭穿 | 让真相被看见 | 他的谎话在舞台上自己裂开 | 台词自相矛盾、关系线打结、当场显形 |
| 三 · 走 | 不再需要他 | 娃娃开始劝你收手 | 报复不再以他为目标 |

第三层的机制表达是**娃娃自己成为收尾机制**，而不是一个设置里的"结束故事"按钮：

- 娃娃随你报复而变强，越强越能演出更狠的戏。
- 但在玩家达到若干节点后，娃娃开始在造景阶段流露迟疑——它说今晚这个戏，我不太想演了。
- 玩家仍可坚持。娃娃不会拒绝，只是会变得安静。
- 玩家接受后进入收尾夜场：娃娃把这段故事合上，主角娃娃带着伤但完整。

这比菜单按钮好，因为它是角色动机而不是产品功能。游戏不惩罚继续报复，但**它唯一的拟人化角色在劝玩家停下来**，这个信号比任何提示文案都有效。一个一直帮玩家报复的娃娃会让人越陷越深，所以娃娃必须是第一个说"够了"的角色。

## 用户旅程

1. 微信收到链接打开，一个空祭坛，娃娃是灰的、安静的。
2. 给娃娃命名、可选头像。
3. **讲述**：一段一段说发生了什么。可以打字，也可以从提供的引子里选（例如"他一开始对我很好"），娃娃会追问（后来呢 / 那时候你说了什么）。
4. **澄清**：娃娃问几件小事——那天是晚上吗、房间里有别人吗、他当时在做什么。问的是感官细节，不是情节。不想说可以跳过。
5. **造景**：娃娃用内置元件把听到的拼成一个俯视的像素房间，几点亮着，几个人站着。出现「它听成了这样」的确认页。
6. **预演**：娃娃先演一小段，然后停下来问：是这样吗？玩家可以说不对，它改。
7. **布场**：拖动角色在房间里的位置，选一个要点燃的节点。
8. **报复**：按下动手。房间里演出后果，娃娃执行，伴随即时反馈。
9. 本夜结束，得到一张战报卡片。
10. 次夜回来：娃娃记得上一次，造景时带上新的前提，角色也在状态里。
11. 若干夜后，娃娃开始迟疑。玩家可以选择收尾，把故事合上。

### 成人向与开放性（2026-09-18 用户追加方向）

用户希望成人向、开放世界与尽可能灵活的关系玩法。当前实现覆盖成年角色的关系冲突、暧昧、夜生活和黑色幽默，采用非露骨表现。角色、房间、物件和动作继续由可扩展数据表定义；“开放”不等于给模型服务器文件/Shell权限。无限角色、自定义地图、自由生成物件与完整开放世界模拟未在本轮实现，后续须独立拆分规格和资源预算。

素材方向：用户允许在自测阶段先比较非商用许可或需署名的可下载素材，追求表现质量；不得以自测为由绕过下载权限或付费。来源与许可保留记录，以便正式发布时替换。

## 协议（草案）

本地站与在线站共用契约，P0 只实现本地站，P1 替换生成来源。

### 讲述 → 记忆

```json
{
  "version": 1,
  "entries": [
    { "id": "e1", "at": "2026-09-17T21:30:00+08:00", "text": "他一开始对我很好，后来就开始不回消息。", "source": "player" },
    { "id": "e2", "text": "长期贬低，说我想太多。", "source": "prompt-option", "corrected": false }
  ],
  "probe": "那时候你说了什么？"
}
```

### 澄清

娃娃只问感官细节，不问情节。问题数 ≤4，可整体跳过。

```json
{
  "version": 1,
  "questions": [
    { "id": "q1", "kind": "time", "text": "那天是晚上吗？" },
    { "id": "q2", "kind": "weather", "text": "外面在下雨，还是晴的？" },
    { "id": "q3", "kind": "room", "text": "房间里除了你们两个，还有别人吗？" },
    { "id": "q4", "kind": "action", "text": "那时候他在做什么？" }
  ],
  "skippable": true
}
```

`kind` 限定在感官/场景枚举内，创作层不得提出情节类或追问动机类问题（如"他为什么这么做"），那是在让玩家复盘伤口。

### 造景

```json
{
  "version": 1,
  "scene": {
    "roomId": "bedroom-window-a",
    "weather": "rain",
    "place": "一间有落地窗的房间，外面在下雨",
    "cast": [
      { "roleId": "villain", "anchor": "window", "facing": "away", "note": "背对着你" },
      { "roleId": "you", "anchor": "door", "facing": "forward", "note": "还没走进去" }
    ],
    "nodes": [
      { "id": "n1", "label": "那句没回的消息", "fromEntry": "e1" },
      { "id": "n2", "label": "他说你想太多", "fromEntry": "e2" }
    ]
  },
  "heardBack": [
    { "claim": "他先靠近，后来退开", "fromEntry": "e1" },
    { "claim": "他让你觉得自己有问题", "fromEntry": "e2" }
  ],
  "uncertain": ["你们最后见面是在哪？"]
}
```

`roomId`/`weather`/`anchor`/`facing` 必须来自内置元件注册表。`heardBack` 是必须项，对应「它听成了这样」确认页。`uncertain` 里的问题会回到澄清或讲述流程，不能由娃娃自行填空。

### 预演

```json
{
  "version": 1,
  "beats": [
    { "kind": "narration", "speaker": "doll", "text": "门是开着的。他背对着你，手机没放下。" },
    { "kind": "line", "roleId": "villain", "text": "我在忙，等一下说。" }
  ],
  "check": "是这样吗？哪里不对，你说，我改。"
}
```

预演 `beats` ≤2，且必须以 `check` 结尾。玩家的否认进入 `corrections`，作为更正写回记忆，并参与次夜造景。

### 剧本

```json
{
  "version": 1,
  "night": 3,
  "title": "他今天声音不太对",
  "beats": [
    { "kind": "narration", "speaker": "doll", "text": "你以为我不会演这场。我会，而且我很想演。" },
    { "kind": "line", "roleId": "villain", "text": "我……我今天嗓子有点……" },
    { "kind": "consequence", "sourceNode": "n1", "text": "他开口，只有气声。她挑了挑眉。" }
  ],
  "aftermath": "他把点单推给她，自己一句话都没说成。",
  "threads": ["他明天会换一种方式解释这件事"]
}
```

约束：`beats` ≤ 5，单条 `text` ≤ 60 字；`roleId`、`sourceNode`、`kind` 必须匹配已注册角色与节点；`threads` ≤ 2 条并写进次夜前提。禁止输出 HTML、脚本、工具指令或外部链接。前端与后端都校验，畸形响应直接回退本地站。

## 报复手段注册表（默认方案，可调）

手段名称、效果类型与代价来自可信注册表。创作层只能改变**文案与表现**，不能改变效果类型、消耗或进度。

| 层 | 手段 | 舞台效果 | 剧情后果类型 |
| --- | --- | --- | --- |
| 恨 | 失声 | 声波断裂动画 | 他今晚说不出一句完整的话 |
| 恨 | 打翻 | 物件倾倒 | 他当众出丑，且找不到原因 |
| 恨 | 失约 | 时钟混乱 | 他迟到、被等、被质问 |
| 揭穿 | 谎话对不上 | 台词气泡自我矛盾 | 两段台词互相矛盾，旁人察觉 |
| 揭穿 | 关系线打结 | 关系线收紧打结 | 他和她的关系出现可见的结 |
| 走 | 缝回自己 | 娃娃被红线缝合 | **不以任何故事角色为目标**，娃娃得到一场自己的戏 |

「走」层的手段**不以反派为目标**，这是第三层的机制保障。

## 内容边界与安全设计

这一节是需求，不是免责声明。

1. **全部发生在舞台内。** 娃娃演的是一场戏，不是一个可执行的计划。游戏不提供任何指向真人的机制——没有定位、联系方式、社交账号、投递入口，将来也不加。台词里没有"你去做什么"，只有"我在戏里把他怎么了"。
2. **不采集可识别的第三方信息。** 昵称 ≤12 字并明确提示不要填真实姓名；头像仅本机。讲述流程提供**引子选项**以降低玩家复述可指认细节的必要性，但不禁止玩家自由讲述。
3. **娃娃不得发明事实。** 见「造景的真实性约束」，对应 HF-06。
4. **收尾不是可选项。** HF-12 与 HF-13 保证游戏有终点，且由娃娃这个角色推动，而不是藏在设置里。设计上不追求最大化停留时长——一个让人反复回到愤怒里的"解压"应用是失败的。
5. **强度可控且可下调。** 讲述时确定的期望强度全程可改；高强度只影响文案夸张程度与动画幅度，不产生更多"伤害值"。
6. **不替代真实帮助。** 当讲述内容涉及暴力、威胁或跟踪时，夜场正常进行，但在合适位置给出一句克制的、非说教式的求助提示，附本地资源入口。不打断玩法，只在明确的边界情形出现。
7. **不做复仇工具。** 战报不含可指认信息（HF-11），分享链接不含玩家输入（HNF-05）。

## 非功能要求

| ID | 要求 |
| --- | --- |
| HNF-01 | 核心触区 ≥44×44 CSS px；输入字体 ≥16px；减少动态偏好有效；操作失败有文字反馈 |
| HNF-02 | 报复的可见反馈 ≤100ms；造景与剧本生成不得阻塞交互，需有加载态；关键资源 gzip ≤250 KiB（不含头像） |
| HNF-03 | 第三方 CDN 不得是可玩前提；P0 关键资源同源；模型服务不可用时全部玩法可用 |
| HNF-04 | 微信拒绝全屏/传感器/震动/常亮时，仍可用触控在页面内完成全部流程；不反复请求被拒权限 |
| HNF-05 | 玩家文本仅作文本渲染；昵称头像仅本机；战报与分享链接不携带任何玩家输入；部署目录不暴露源码与密钥 |
| HNF-06 | 每个任务可追踪到需求与验收；模拟器验证与真机验证分开报告 |
