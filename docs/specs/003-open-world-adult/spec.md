# 003 · 开放关系世界与成人表现层

状态：SDD 规格；`legacy-v2` 已有部分 Node/JavaScript 原型能力和本地测试证据。004 已提供 Python World Kernel、TypeScript 单人入口、草稿确认/CAS、旧档导入强制 SFW 和移动端基础闭环，但 003 的关系、多目标结算、成人策略与分享降级仍未迁移（对应 004 `MW-15` 待开始）。微信真机与公网验收待完成。更新：2026-09-20（Asia/Shanghai）。

本规格承接 002 巫柜夜场。它把用户追加的“开放世界”和“R18 元素”拆成可以逐项验收的能力，避免把未实现的自由生成误写成现有功能。002 的默认玩法继续是成年虚构角色、关系冲突、暧昧、夜生活和黑色幽默，默认 SFW、非露骨。

## 目标

玩家可以在多个相连房间、多个成年虚构角色和持续关系状态中自由讲述与布场。房间、角色、物件、动作和关系边都来自可版本化的注册表，模型负责选择和表达，不能直接创造权威世界状态。

成人模式是表现层而不是权限层。玩家明确开启并通过服务端年龄门槛后，可以出现成熟暧昧、亲密关系、成人幽默和淡出式后果；默认、分享卡片和不满足策略条件的会话始终回到 SFW。成人模式不提供露骨色情、裸露生成、性暴力或强迫，也不允许针对真实人物的羞辱、色情化或可识别信息。

## 核心循环扩展

`讲述 → 澄清 → 造景 → 预演 → 确认 → 布场 → 演出 → 关系变化 → 写入记忆`

玩家可以在已注册的房间之间移动、增删舞台人物、提出关系动作和改变强度。所有改变先作为草稿预演，只有确认后才写入版本化世界。断网时使用同构的本地注册表和模板。

## 多目标诅咒与组合关系

一次仪式可以针对一个目标集合，而不是只能选一个人。玩家可以说“让 A 和 B 一起面对这件事”，娃娃将目标集合拆成各自可见的反应，再由环境和关系边呈现共同后果。目标必须是舞台里的成年虚构角色或注册的泛指路人，不能是现实中可识别的人。

目标集合有稳定的 `targetSetId`，包含 1–4 个角色、关系节点和一个表现强度。每个角色 agent 只收到自己可见的已确认事实与公开舞台事件；娃娃可以看到玩家私下讲述，环境只能处理物件和可观察后果。一个角色的拒绝或模型失败不会让其他目标的本地演出消失。

多目标仪式仍是草稿 → 预演 → 玩家确认 → 原子结算。确认后一次性写入所有目标的关系变化和事件来源；取消、过期、回退或撤回不能只撤掉其中一个目标。玩家可以在下一夜对同一 `targetSetId` 追加、减少或撤回关系后果，产生新版本而不修改历史事件。

## 需求

### P0：开放关系世界

| ID | 可验证行为 |
| --- | --- |
| AW-01 | 世界注册表定义房间、连接、家具、站位、天气、可见物件和 affordance；至少支持 6 个房间和跨房间移动。 |
| AW-02 | 房间切换、人物在场、关系边和事件后果跨夜保存；离线演出使用同一注册表的本地模板。 |
| AW-03 | 关系边至少支持 `trust`、`tension`、`secret` 三类，数值有范围、来源事件和可见性；下一幕会受已确认变化影响。 |
| AW-04 | 模型只能引用注册表中的 room/edge/node/use/beat；未知 id、越权角色、越界数值和任意 world mutation 必须丢弃并使用本地回退。 |
| AW-05 | 动态加入人物或地点必须由玩家确认并产生版本号；不得因模型一句话静默扩张世界。 |
| AW-06 | 320/390/430 CSS px 下房间、角色、关系提示和输入区不重叠；移动端关键流程不依赖 hover。 |

### P0：多目标仪式

| ID | 可验证行为 |
| --- | --- |
| MT-01 | 一次仪式支持 1–4 个目标角色，目标集合有稳定 ID、顺序无关的成员列表和可见的关系节点；旧单目标存档迁移为单成员集合。 |
| MT-02 | 玩家通过自然语言增删目标、切换房间和选择组合手段；界面不提供绕过娃娃 agent 的直接伤害按钮。 |

| MT-06 | 下一夜可引用同一目标集合的已确认后果；玩家可追加、减少或撤回目标关系，历史事件保持不可变并可追溯。 |

### P0：成人表现层

| ID | 可验证行为 |
| --- | --- |
| AD-01 | 每个会话有服务端控制的 `contentLevel`：默认 `sfw`；`mature` 只有在年龄确认、地区/渠道策略允许且玩家主动开启后可用。客户端不能通过 `r18=true` 绕过。 |
| AD-02 | 成人层只允许成年、虚构角色之间的暧昧、亲密、成人幽默和非图形化、淡出式后果；默认不描述露骨性行为或裸露。 |
| AD-03 | 以下内容始终拒绝并回退 SFW：未成年人或疑似未成年人、性暴力/强迫、图形化性行为、裸露生成、真实人物定向羞辱/色情、跟踪或现实伤害计划。 |
| AD-04 | 输入、草稿、最终 beats 各经过服务端 policy gate。拒绝不落盘、不推进夜数，并返回可理解的降级提示；单角色命中不阻断其他角色。 |
| AD-05 | 成人策略不增加 agent 工具权限。娃娃、人物和环境仍只能调用既有注册工具，无 Shell、文件、网络、外链或任意状态写入。 |
| AD-06 | 从 `mature` 切回 `sfw` 时，未确认草稿全部作废；已确认世界可继续但下一幕按 SFW 重写。策略版本和 reason code 可审计，普通日志不保存敏感原文。 |
| AD-07 | 战报、分享卡片和公开链接永远输出 SFW 摘要，不含成人原文、玩家输入、头像、真实姓名或敏感关系细节。 |
| AD-08 | 头像、角色资料和文本默认只保存在会话允许的范围；不把成人模式变成上传头像或收集第三方身份信息的入口。 |

## 约束

- “开放世界”是注册表、关系图和可确认扩展的组合，不是模型自由生成视觉、无限 NPC 或外部世界操作。
- 全部角色必须被标记为成年虚构角色；玩家昵称提示不要填写真实姓名，角色名只用于舞台文本。
- 成人模式不改变 002 的隐私隔离、CAS、幂等、取消、迟到结果隔离和无模型可玩性。
- 不把内容策略寄托在提示词上。契约校验、策略 gate 和本地 fallback 必须独立存在。
- 任何后续更宽松的内容范围都要新建规格、验收样例和渠道策略，不能通过修改客户端常量上线。

## 非目标

本规格不实现无限地图、用户上传或生成裸露/色情图片、真实人物定向报复、自动联系第三方、后台自主运行的多 agent 社会，也不承诺微信或应用商店允许 mature 内容。正式发布前必须分别完成渠道和年龄门槛评估。

## 数据契约草案

```json
{
  "worldVersion": 4,
  "contentLevel": "sfw",
  "policyVersion": "adult-1",
  "rooms": ["bedroom", "bar", "office"],
  "targetSets": [
    { "id": "pair-a-b", "members": ["A", "B"], "relationNodes": ["secret"], "intensity": "sharp" }
  ],
  "relations": [
    { "from": "A", "to": "B", "kind": "tension", "value": 42,
      "sourceEvent": "night-3-beat-2", "visibility": "public" }
  ],
  "policy": { "ageConfirmed": false, "channel": "web", "region": "unknown" }
}
```

模型输出仍使用 002 的剧本契约；新增字段只能引用注册表 ID。`contentLevel`、`policyVersion` 和 gate reason 由服务端写入确认事件，不接受来自模型或浏览器的权威值。

## 验收示例

1. 新会话和未完成年龄确认只生成 SFW；伪造客户端参数不能获得 mature。
2. mature 下的成年虚构角色暧昧台词可以通过，露骨性行为、强迫、未成年暗示、真实人物姓名和提示注入均被拒绝或改写为 SFW 模板。
3. 未知房间、物件、关系边和动作 id 不会写入 SQLite；重新生成仍能完成一幕。
4. 两个匿名玩家可拥有同名角色但不能读取对方世界、策略或关系事件。
5. 关闭 mature 后刷新、重连、分享和战报均为 SFW；服务端记录策略版本与 reason code，不记录敏感原文。
6. 对 A+B 的组合仪式确认后，A、B 各自的可见记忆和共同关系边都只结算一次；撤回关系边不会删除历史战报，也不会影响另一玩家的世界。
