### 语言与部署边界

TypeScript 与是否有服务端是两个独立决策。正式世界继续由 Python FastAPI World Kernel 管理共享时钟、事件、模型密钥、策略和跨设备存档；Node/Pi `legacy-v2` 只作为兼容回退。项目可以另外提供纯 TypeScript 的本地单机模式（IndexedDB + Web Worker + 本地规则 Agent），用于离线试玩和无模型回退，但该模式不拥有正式世界权威，不提供多人共享、跨设备同步或可靠后台推进。未来若把 Kernel 改成 Node/Deno/Bun，必须先通过同一事件、能力、可见性、CAS、回放和迁移契约，不能把语言迁移写成无服务化完成。

## 目标

玩家通过手机微信打开 H5，在一个可持续的像素世界中扮演 `YOU`。产品形态是开放世界 Galgame：玩家可以在已发布地点之间自由移动，剧情由共同在场、统一时间、人物关系、角色目标和可重放的随机遭遇共同产生，而不是按固定章节强制播放。玩家拥有巫毒娃娃，但不能直接操控其他角色。娃娃与玩家身体共用一个执行 Agent，外观上仍显示为两个概念：`DOLL` 是能理解玩家意图并执行仪式的巫毒媒介，`YOU` 是世界里说话、移动和使用物件的身体。A–Y 是独立的人物 Agent；当前只注册 A、B、C 三名主要角色，Z 是可以反复复用的临时龙套槽位。环境 `ENV` 负责世界反馈和规则结算，不代替任何人物做决定。

目标不是让模型拥有世界权限，而是建立一个可重放、可验证、无模型也能运行的社会模拟内核：Agent 只能提交行动提案，Python World Kernel 校验可见性、能力、前置条件和目标状态后，才生成权威事件。

## 已确认要求与实现默认

### 用户已确认

- 前端采用 TypeScript，面向手机和微信 H5。
- 后端采用 Python，首选 FastAPI；世界状态由后端权威管理。
- 大模型通过可替换 Agent Adapter 接入，不能直接写数据库或调用任意工具。
- 玩家不能直接控制 A、B、C 或 Z。玩家只能通过 `DOLL` 让 `YOU` 说话、移动、观察、邀请、询问、布置场景或使用巫毒能力。
- `YOU` 与 `DOLL` 共用一个执行 Agent；`YOU` 不再创建独立的玩家模型 Agent。
- 每个长期人物 Agent 都有自己的记忆、目标、立场、能力和回应选择；他们可以拒绝、误解、撒谎、反问、沉默、离开或反击。
- A–Y 是有意义的长期角色槽位；当前 A–C 是主要角色。Z 是可复用的路人/临时角色槽位，不能写入长期目标集合，除非将来另行确认注册为长期角色。
- 角色可以和环境物件互动，也可以与其他角色互动；每个可接受交互必须有能力和可见性约束。
- 玩家先叙述人物、地点、关系与故事前提，再由世界搭建模型补齐世界圣经、地点图、角色目标/秘密、时间表和遭遇候选；任何补齐内容都必须先预览并由玩家确认。
- 世界运行采用分层 Agent：世界搭建阶段可用高能力模型，`PLAYER_DOLL` 使用较强的意图理解模型，当前激活的 A–Y/Z 使用快速模型或本地规则；未激活人物不持续调用模型。
- 无模型、断网、模型超时或模型返回非法结果时，核心玩法仍可完成。
- 环境工具遵循 [决策 0007](../../decisions/0007-world-interaction-tool-boundary.md)：运行时只能调用版本化原子能力和已发布实体 affordance；动态生成只产生待确认的声明式草稿，不产生可执行代码。
- 首次进入必须提供一段可实际完成的 Galgame 新手序章，并同时提供“开始新手故事”和“自己设计世界”两个清楚入口。教程必须用剧情、当前目标和直接行动教会玩家搭建世界、观察、移动、对话和做选择，不能只展示功能说明或要求玩家先理解自由文本命令。
- 新手序章完成后进入同一权威世界的自由模式；刷新或恢复会话后保持已完成步骤，不重复已经提交的世界变更。自定义入口必须提供可直接仿写的故事模板，让玩家知道怎样描述地点、当前处境、关键角色、角色诉求和即将发生的事件。
- Galgame 是对话型开放世界：人物各有统一世界时间下的工作与生活表。新手序章必须展示至少一名人物的公开行程和可交互时间窗；玩家未在该人物在场时抵达，当前机会关闭或转入另一剧情分支，不能让人物为教程永久等候。

- 剧情提示需要像 Galgame 一样通过对话窗呈现，能看清当前人物是谁、正在说什么或思考什么；用户提供的图片用于说明角色名牌与文字窗的交互形式。

## 统一世界时钟、时间表与按需激活

### 设计边界

每个世界只有一个服务端权威 `WorldClock`。客户端的系统时间只用于显示倒计时，不能推进世界，也不能决定角色当前地点。首版时钟以世界配置的时区解释日历时间（默认 `Asia/Shanghai`），用服务端单调时间换算 `day/minute`；`speed=1` 表示现实一分钟推进游戏一分钟。暂停、加速、回溯和换时区属于受保护的管理命令，不接受普通玩家请求。

角色不会因为世界时钟每秒变化而调用模型。时间推进只运行确定性投影：根据已发布的时间表计算角色在当前时间段的预期房间、区域、活动标签和是否公开可见，并追加 `clock_advanced`、`presence_projected` 等可重放事件。角色只有在玩家进入其兴趣范围、对其发起交互，或一个已排队的世界事件需要回应时才取得激活租约并调用 Agent。

### 时间表与驻留投影

时间表是版本化注册表，不是模型生成的即时事实。每个块包含 `agentId`、重复规则、起止分钟、优先级、容差、`roomId`/`zoneId`、公开活动标签和例外日期。重叠块按优先级和稳定 ID 解决；没有命中时使用角色的默认驻留点。时间表只声明“此刻应该在哪里/做什么”，不凭空写入角色的私密想法或已经发生的剧情。

```json
{
  "id": "A-workday",
  "agentId": "A",
  "recurrence": { "kind": "daily", "days": [1, 2, 3, 4, 5] },
  "startMinute": 540,
  "endMinute": 1020,
  "location": { "roomId": "office", "zoneId": "desk" },
  "activity": "work",
  "priority": 20,
  "toleranceMinutes": 15,
  "visibility": "public"
}
```

Kernel 保存由时间表导出的 `PresenceProjection`：`agentId`、有效时间窗、地点、活动标签、来源块和 `projectionVersion`。它是可重建的事实投影，不是角色 Agent 的心理状态。玩家看到的是公开地点和活动标签；角色的私密时间表、目标和记忆仍由 Context Builder 单独过滤。

### Agent 生命周期状态机

```text
dormant
  -> staged       (时间表命中，只有确定性驻留投影)
  -> active       (玩家进入兴趣范围/发起交互/收到排队事件)
  -> quiescing    (玩家离开范围或回合结束，写入短期摘要)
  -> dormant

active -> fallback  (模型超时、429、非法输出；本地规则完成本回合)
fallback -> active   (仅当前回合；不改变角色长期能力)
```

`staged` 不运行模型、不执行吃饭/工作等细节，只让场景知道角色位于何处。`active` 由 `ActivationLease` 绑定到玩家会话和 `roomId/zoneId`，有 TTL 与心跳；租约失效先进入 `quiescing`，不能留下一个永不释放的后台 Agent。激活时 Context Builder 提供从上次 checkpoint 到当前 `WorldClock` 的时间摘要、公开事件、角色自己的短期记忆和当前可见人物；它不会逐分钟补演未观察的生活，也不会把玩家不在场时的模型推理当成事实。离开时只提交经过 Kernel 校验的公开事件和短期摘要，摘要失败则丢弃，不阻塞世界时钟。

首版兴趣范围按 `roomId + zoneId` 计算；没有坐标时，同房间视为进入，跨房间视为离开。以后增加像素坐标时，保持同一事件契约，把范围判断替换为注册表的 `activationRadius`，不改变 Agent 权限。

### 随机剧情与世界观察者

进入兴趣范围可以触发随机遭遇，但随机性必须由 `(worldId, clockDay, clockMinuteBucket, sceneId, encounterVersion)` 生成稳定种子，并在事件中记录；重复拉取、刷新或重连不得重抽。遭遇候选来自房间/关系/角色注册表，模型只能选择台词和合法回应，不能创造未注册人物、地点或关系边。

建议保留一个逻辑 `WORLD_OBSERVER`，但它不是每秒运行的超级 Agent，也不代替角色做决定：

- 确定性审计在每次时钟投影、激活提交和世界保存前运行，检查时间表冲突、角色位置越界、事件版本、可见性和关系范围。
- 观察者模型只对最近产生新事件或异常的活跃世界运行低频批次（首版默认至少间隔 15 个游戏分钟，并在激活后或异常事件后合并触发），读取脱敏的公开摘要，输出 `audit` 或 `correction_proposal`。没有新事件的无人世界不调用观察者模型；观察者不能直接写状态、读取私密记忆或命令角色。
- Kernel 可自动执行的修复仅限确定性投影（例如把未激活角色放回当前时间表地点、丢弃未知事件）；涉及事实、关系或角色意志的偏差只记录并等待下一次合法交互，不能静默改写剧情。
- 审计事件包含 `observerVersion`、问题码、依据事件和处理结果；修复必须产生新事件，历史事件不可变。观察者不可用时，世界继续按时间表和本地规则运行。

### 角色分层与世界搭建

高能力模型可以在“建世界/发布注册表”阶段根据玩家叙述提出世界圣经、地点图、人物目标与秘密、关系、时间表和遭遇表草稿。它可以补全因果链、标出冲突并在缺少关键事实时向玩家提出少量澄清，但不得把未回答的问题自行写成确定事实。草稿必须经过注册表校验和玩家确认，才成为版本化世界数据；以后扩建地点、增加人物或改变世界观也走相同的预览/确认流程。

运行期使用按职责配置的模型路由，而不是让一个模型扮演整个世界：

| 职责 | 调用时机 | 建议模型档位 | 用户交互边界 |
| --- | --- | --- | --- |
| `WORLD_BUILDER` | 首次建世界或玩家明确发起扩建 | 高能力、低频 | 可以围绕草稿向玩家澄清；确认后退出当前运行回合 |
| `PLAYER_DOLL` | 玩家输入意图或使用巫毒能力 | 较强、低延迟 | 是常驻的玩家入口，只能控制 `YOU` 和已注册的娃娃能力 |
| `A–Y/Z` | 角色被激活并需要作出选择 | 快速、低成本 | 只代表自己回应或行动，不能代表世界或其他角色 |
| `WORLD_OBSERVER` | 低频批次、激活后或异常后 | 可选审计模型 | 不作为角色与玩家聊天，只输出审计或纠偏提案 |
| `ENV` / Kernel | 每次合法动作结算 | 确定性 resolver 优先 | 只产生系统/场景反馈，不接受对话来绕过规则 |

模型档位由服务端按职责、预算和可用性配置，不在世界数据中硬编码供应商。切换模型只能改变理解和表达质量，不能扩大工具、记忆、可见性或世界写权限。无模型时，世界搭建使用受限模板，人物和 ENV 使用本地规则完成核心闭环。

### 工具目录、环境交互与 ToolCompiler

环境交互不按每辆车、每盏灯或每条地铁线路创建独立模型工具，也不允许运行时模型生成函数。工具分为三层：

1. **原子能力**：由 Kernel 版本化维护，例如 `move`、`use_object`、`toggle`、`board`、`travel`、`alight`、`operate_vehicle` 和 `wait`。
2. **实体与 affordance 注册表**：世界草稿声明车辆、灯、门、站点、线路、站位等实体的类型、状态、可用动作和前置条件；确认发布后才可被运行时看到。
3. **组合动作计划**：例如“开车去公司”“乘地铁到酒吧”“骑车回家”由已发布的原子能力组成可重放计划，不能由模型临时拼出新代码。

运行时流程固定为“Agent 提交意图 → Kernel 校验地点、能力、前置条件和权限 → resolver 结算状态与时间 → ENV 产生可观察反馈”。车辆、地铁和自行车共享移动能力，由实体类型、路线和班次数据表达差异；灯光、门和家电共享物件状态 resolver。角色未激活时只推进时间表和预计到达投影；玩家进入兴趣范围后，才把可观察的乘车、驾驶或开灯步骤展开为事件。

未被观察的跨地点活动采用“行程投影”而不是后台表演：Kernel 只保存出发地、目的地、预计出发/到达时间和交通方式。若玩家在途中进入同一车厢、道路或站点，当前行程才被物化为可交互场景；否则到点后只提交一致的驻留投影。这样角色看起来拥有连续生活，又不会为无人观看的吃饭、通勤或工作持续消耗模型。

`ToolCompiler` 只在世界搭建阶段运行：把玩家叙述和高能力模型输出编译为受 schema 约束的工具/实体草稿，检查未知能力、参数、引用、可达性和副作用，生成预演结果，等待玩家确认后写入带版本的注册表。运行时未知 `toolId`、未发布实体、任意代码、网络/文件操作和直接写关系或位置的提案一律拒绝并记审计。

当前实现默认：已注册房间内的实体、公开重复日程和公开遭遇候选可以同批预览并确认发布；按照稳定 ID 合并，不提供隐式删除。预览关联基础版本和声明哈希，确认必须通过版本与内容校验；重复确认包括重启重试只能返回同一结果。任何声明非法或事务失败时整批不生效，取消的草稿不能被其他服务实例重新发布。新增房间、例外日期、非零容差、私密日程与新角色注册暂时明确拒绝，不得静默忽略后宣称已搭建。

### 生命周期需求

| ID | 可验证行为 |
| --- | --- |
| WL-01 | 同一世界的 `/world`、事件和所有 Agent 上下文使用服务端 `WorldClock`；客户端时间或伪造 `day/minute` 不能推进时钟。 |
| WL-02 | 时间表以版本化块定义角色的重复时段、地点和活动；重叠和例外按确定性规则解析，结果包含来源块与投影版本。 |
| WL-03 | 角色在未进入兴趣范围时保持 `dormant/staged`，只更新驻留投影，不调用角色模型，也不生成逐分钟生活事件。 |
| WL-04 | 玩家进入 `roomId/zoneId` 或发起交互时创建有 TTL 的激活租约；激活上下文包含时间摘要和可见事件，离开后释放租约并保存短期摘要。 |
| WL-05 | 激活期间的角色行动仍需独立 Agent 提案、能力/可见性校验和原子事件提交；模型失败只回退当前角色，不阻塞其他角色或统一时钟。 |
| WL-06 | 随机遭遇使用可重放种子和注册表候选；重连、刷新和事件补拉不会重复触发或重新抽签。 |
| WL-07 | 确定性观察者检查时钟、时间表、位置、事件和关系不变量；模型观察者只能输出审计/修复提案，不能直接改世界或角色意志。 |
| WL-08 | 世界搭建模型只能提交注册表草稿；未确认的房间、角色、时间表、关系和遭遇不得进入运行时或人物上下文。 |
| WL-09 | 运行时环境交互只能引用已发布的原子能力、实体 affordance 和组合动作模板；模型不能生成可执行工具代码，未知工具必须被拒绝并产生审计事件。 |
| WL-10 | `WORLD_BUILDER` 只在建世界/扩建时与玩家协作，`WORLD_OBSERVER` 只读审计，`ENV` 只结算并反馈；日常玩家入口保持为 `PLAYER_DOLL` 和当前在场人物。 |
| WL-11 | 服务端按职责路由模型和预算；世界搭建、娃娃、人物和观察者可以使用不同模型，但切换模型不得改变权限、可见性、事件合同或无模型回退。 |

## 世界实体与控制边界

| 实体 | Agent 身份 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| `PLAYER_DOLL` | 玩家与巫毒娃娃共享的执行 Agent | 理解玩家输入；让 `YOU` 观察、说话、移动、询问、邀请、使用已注册物件；施放显形、延迟、冷场、绑定、守护、净化等受限能力 | 直接改写 A–Y 台词、强迫角色接受、越过能力/可见性校验、直接写世界状态 |
| `YOU` | `PLAYER_DOLL` 控制的世界实体，不是独立模型 Agent | 出现在房间；以公开身份说话、移动、观察和操作物件；接收公开回应 | 控制其他人物；读取不可见私密记忆；凭空拥有未授权能力 |
| `A–Y` | 独立人物 Agent 槽位 | 感知自己可见的事实和事件；发起或接受交互；自主选择回答、拒绝、撒谎、反问、离开、反击或保持沉默；与物件互动 | 读取其他角色私密上下文；直接写关系/位置/道具；调用模型外工具；被玩家直接命令 |
| `Z` | 临时人物 Agent 槽位 | 在当前场景中作为路人或一次性角色参与；拥有短期记忆和注册能力 | 默认写入长期角色档案或长期目标集合；冒充 A–Y；跨场景永久保留而无确认 |
| `ENV` | 世界反馈/规则 Agent（无个人意志） | 校验物件和场景动作；更新天气、灯光、声音、门、道具和可观察现象；把公开事件投影到场景 | 替人物决定立场、编造玩家未确认的事实、私下改变角色关系、调用外部世界 |

任何客户端请求都先作为意图或行动提案进入 Kernel。客户端传入的 `actor`、`target`、`relation`、`effect` 和数值都不具有权威性。

## 角色能力模型

每个角色注册项必须声明：

```json
{
  "id": "A",
  "kind": "person",
  "ageStatus": "adult-fictional",
  "goals": ["protect_secret"],
  "traits": ["defensive", "proud"],
  "capabilities": {
    "outgoing": ["speak", "ask", "deny", "lie", "leave", "use_object"],
    "incoming": ["question", "invite", "accuse", "offer", "bind"]
  },
  "memoryPolicy": { "private": true, "retention": "session" }
}
```

能力分为四类：

1. 感知：读取房间内公开事件、可见物件、在场人物和自身记忆。
2. 人际行动：`speak`、`ask`、`answer`、`deny`、`lie`、`counter`、`offer`、`refuse`、`silence`、`leave`、`invite`。
3. 环境行动：对注册物件执行 `look`、`take`、`use`、`move`、`ring` 等白名单动作。
4. 巫毒媒介行动：仅 `PLAYER_DOLL` 可提交，必须映射到注册的场景条件或状态效果，不能替换目标角色的决定。

发起能力和被交互能力分开校验。例如 A 可以接受 `question`，不代表 A 必须 `answer`；A 可以拥有 `lie`，不代表任何玩家输入都能要求 A 撒谎。能力结果由目标 Agent 提案，Kernel 决定是否有效。

## 事件与微回合

### 标准流程

```text
玩家输入
  -> PLAYER_DOLL 解析为意图
  -> YOU 提交公开行动提案
  -> Kernel 按在场、距离、能力和可见性筛选目标
  -> 目标 A/B/C/Z 各自在隔离上下文中感知并提交回应提案
  -> Kernel 校验并原子提交公开事件、关系变化和物件状态
  -> ENV 生成确定性反馈及可选旁白
  -> 更新各 Agent 记忆
  -> SSE 推送可见事件；客户端重放舞台
```

玩家说“让 A 和 B 当面对质”时，唯一合法的解释是由 `YOU` 发起一组公开行动：把 A、B 邀请到同一房间，分别向两人提问或施压。系统不得生成 `actor=A, action=confront, target=B` 的玩家直控动作。A、B 是否互相回应由各自 Agent 决定。

### 事件契约草案

```json
{
  "eventId": "evt_01J...",
  "worldVersion": 17,
  "turnId": "turn_42",
  "actor": "YOU",
  "action": "ask",
  "target": "A",
  "channel": "public",
  "payload": { "text": "你愿意当着 B 的面解释吗？" },
  "visibility": { "audience": ["YOU", "A", "B", "ENV"] },
  "source": "player_doll",
  "proposalStatus": "accepted"
}
```

目标回应使用独立事件，合法 `responseKind` 包括 `answer`、`deny`、`lie`、`counter`、`silence`、`leave`、`refuse`。环境反馈必须引用触发事件，不得凭空增加秘密事实。一个目标模型失败时，该目标使用本地回应模板；不能阻塞其他目标，也不能把失败结果当成成功。

## 可见性、记忆与隐私

事件通道至少包括：

- `public`：房间内在场角色、YOU、ENV 可感知；进入公开记忆。
- `private`：仅指定发起者和目标可感知；不推送给其他角色或前端旁观者。
- `doll_private`：玩家与 PLAYER_DOLL 的私密意图；不能进入人物上下文。
- `environment`：ENV 产生的可观察反馈；只有在场者收到。
- `system`：Kernel 的版本、拒绝、回滚和审计信息；不作为人物事实。

每次 Agent 调用必须由 Context Builder 按角色过滤：已确认事实、在场公开事件、该角色可见关系边、自己的记忆和当前可用能力。未确认草稿、其他角色私密记忆、玩家真实身份和服务端密钥永不进入角色上下文。记忆更新只在事件原子提交后发生；被拒绝或取消的提案不写入记忆。

## 重放、版本与无模型回退

- 每个世界有单调 `worldVersion`；命令带 `expectedVersion`，冲突返回可重试的版本错误。
- 每个微回合有 `turnId` 和幂等键；重复确认只返回原结果，不重复扣费、改关系或写记忆。
- 事件日志保存 `eventId`、schema 版本、输入摘要、通过的提案、随机种子、resolver 版本、模型/回退来源和可见性，不保存不必要的敏感原文。
- 重放从快照和 append-only 事件恢复房间、位置、物件、关系、记忆索引及前端演出；不重新请求模型，不依赖当前模型版本。
- 无模型路径必须实现同一事件契约：本地意图解析、能力校验、A–Y 响应模板、ENV 反馈和前端动画都可运行。模型只是表达质量增强器，不是玩法前置条件。

## 单人预发布闭环

首个可交付入口是同源单人世界，不要求注册账号。服务端用随机、不可由客户端选择的 `HttpOnly` cookie 绑定一个持久 `worldId`；请求体中的 `worldId`、`viewer` 或路径参数不能切换到其他玩家的世界。Cookie 只代表匿名世界所有权，不替代后续账号体系或跨设备同步。

玩家首次进入后按“叙述故事 -> 查看世界草稿 -> 确认或取消 -> 输入行动 -> 查看行动预演 -> 确认或取消”完成闭环。故事草稿和行动草稿在确认前不得推进权威世界版本；确认写入幂等回执，同一 `draftId`/`turnId` 重试返回首次结果。移动确认后，服务端以玩家的新房间刷新兴趣范围，只有新范围内的角色才会被激活；后续询问仍由目标角色自主回应。

匿名会话、世界快照、草稿、确认回执和角色资料保存在同一个 SQLite 数据库中，进程重启后凭原 cookie 恢复。导出结果使用版本化 schema；导入只写当前 cookie 所属世界，支持当前单人格式和既有 `voodoo-hex-v5` / `voodoo-cabinet-v1` 的受控迁移，且强制保持默认 SFW。导入成功不删除浏览器旧 key，失败不覆盖当前世界。

预发布服务必须同源提供 `dist-hex/index.html` 和其构建资产，只允许明确的静态文件路径，不能暴露仓库源码、`.env`、SQLite 文件或目录列表。写请求限制 JSON 体积并校验 `Origin`/同源关系；内部 tick 和审计接口仅接受服务端配置的管理令牌，未配置令牌时保持关闭。桌面模拟、微信真机和公网外部访问分别记录，任何一项不能相互替代。

浏览器本地缓存只用于加快渲染和保留旧版导入来源，不是权威状态。启动时必须先显示可操作的加载或恢复界面，再校验缓存版本与结构；遇到旧格式、截断 JSON、字段缺失或不兼容值时，不得因未捕获异常停在白屏。可迁移的旧缓存进入受控导入预览；不可迁移的缓存只隔离对应坏记录，并尝试从 cookie 所属服务端世界恢复。服务端世界也不可用时，回到可重新开始的首次进入界面，同时保留可理解的中文错误和重试入口。

主游戏界面必须直接展示服务端快照推导出的当前地点、可到达地点和当前在场角色。每个可到达地点和在场角色都提供触控可点击行动；点击地点生成既有移动预览，点击角色生成既有询问/互动预览，仍需经过 Kernel 校验和确认，不允许前端直接改位置或替角色决定。自由文本继续保留，用于这些快捷行动之外的表达。

故事生成、行动预览、确认、取消、恢复和导入等请求必须显示明确的处理中状态，并在操作结束前禁用会造成冲突或重复提交的控件。重复点击或网络重试必须复用同一草稿、回合或幂等键，不能产生第二次世界变更。产品界面按稳定错误码显示中文说明和可执行的恢复动作；原始异常、英文协议消息和堆栈只用于受控诊断，不直接作为玩家提示。

首次进入页必须把“开始新手故事”作为无需自由输入即可开始的可玩入口，同时保留“自己设计世界”。新手故事不是帮助页：它先生成一份可确认的完整世界草稿，再在游戏内依次给出单一、明确的章节目标和对应直接行动，至少覆盖观察场景、查看人物公开行程和当前时间窗、移动到人物所在地点、与人物交谈和一次会改变后续台词或目标的回应选择。每一步继续使用既有故事/行动预览、确认和 Kernel 校验；推荐按钮与自由输入的可见交互区别按 SP-18，教程状态只记录教学进度，不得成为第二套位置、时间、关系或剧情权威。

教程中的人物在场和机会有效性由服务端 `WorldClock`、公开日程与 `PresenceProjection` 判定。前端可以显示当前时间、公开行程和剩余机会提示，但不能用本地倒计时决定人物是否在场。若玩家等待或绕路而错过时间窗，服务端关闭该交互机会或返回替代目标/分支，界面需要解释已经发生的变化并继续保持可玩；刷新、重连和修改设备时间不得把机会重新打开。

自定义入口使用结构化示例帮助玩家写出可玩的起始冲突，至少呈现地点、玩家当前处境、关键角色、各方诉求和马上会发生的事件。系统可把结构化字段合成为世界叙述，也可以给出一段完整可编辑范文；在玩家提交前，不得把示例人物或事实混入其世界。教程完成后保留当前人物、地点、事件和选择结果，界面将当前目标切换为自由行动，而不是另建存档或重置世界。

推荐动作是已发布世界的只读提示：优先展示当前章节目标，再提供当前场景可操作的物件、在场人物、移动和等待选项。每个动作应使用玩家能读懂的文案说明意图及预计耗时；推荐动作一次点击由客户端完成预览与确认，Kernel 在确认时仍重新检查在场、物件范围、能力和版本；自由输入显示可确认/取消的预览。自由输入与推荐动作走同一套解析和结算；对“去开门，看看里面有啥东西”等自然表达，先识别当前场景物件和动作，不能因“去”或泛指“房间”误判为地点移动。无法支持的输入须保留原文，说明当前支持范围并显示可选动作，不生成虚假的成功反馈。

主人公的生活主线由服务端发布并投影为公开提示，包括身份、今日职责、地点、时间和完成状态。首篇默认主人公在城市档案馆做校对，工作在办公室通过已注册办公桌交互完成，确认后才推进时间并保存结果。主线允许玩家绕路、探索或错过机会；错过人物交谈不能把人永久留在原地，也不能卡住其他工作、探索与存档。章节、工作结果和分支存于所属 world 的权威记录，前端只展示 `guidance`；切换 cookie/world、刷新或导入后以对应世界恢复，不能挪用另一个世界的本机教程进度。完整梗概和逐章行为见 [tutorial-story.md](tutorial-story.md)。

本次对话窗的实现默认是角色名牌、逐句文字和清楚的“下一句”入口，分别标识公开对白、主角心声和环境叙述。每个已确认章节阶段可有多句演出，玩家点击或使用键盘阅读；读完后展示当前推荐选项，也可提前展开行动，以免阅读界面遮住时间敏感的操作。自由表达的可见预览/确认继续保留，推荐按钮按 SP-18 串联原服务端流程。阅读只改变界面游标，不消耗行动时间、不确认选择、不推进章节，也不暂停服务端世界时钟；阅读期间错过人物窗口，仍由 Kernel 在行动确认时判定。

对话文本来自服务端公开 `guidance`，不通过展示层读取 NPC 私密记忆或推测其真实想法。本切片 `thought` 仅允许 `YOU` 的已编写主角心声；NPC 的沉默、表情和动作只以可观察叙述表现。阅读位置按所属 world 与对话内容标识恢复，当前段落已显示到当前位置的文本可回看；刷新不重复结算世界行动，切换世界不串用游标。以上逐句方式、键盘操作、推荐选项展开方式与字段均是本次实现默认，不代表用户逐项指定；不包含立绘、配音或商业游戏素材移植。

教程应承认已经做过的事，不能把固定按钮顺序当作世界规则。先开客厅门、再读便笺仍满足已完成的开门事实；玩家已通过合法移动离开客厅，出发引导不应继续要求回去开门。当前地点和已确认事实用于确定尚未完成的目标，尚未阅读的便笺、站内告示或工作不能自动补全。已有存档若停在与事实不符的章节，服务端以可审计事务修正教程进度，不重做玩家行动、不再扣行动时长，也不修改已错过的时间窗或既有结局。

日常交谈需要给出具体可继续的话题。首篇默认给周野提供日常、站内告示、三分钟与后续追问的明确回应；“说什么”“什么意思”“然后呢”“继续说”等接话表达优先关联最近仍同场的已确认交谈对象，否则只在当前有唯一可交谈对象时补全目标。多名在场人物且没有有效上下文时明确让玩家选择对象；不把未注册行动或任意未知文本默认为聊天。无法解析时保留原文与用户记录，立即展开当前推荐动作、具体人物交谈入口与恢复提示，不要求先读完整段对白才能找到出口。

## 成人表现和安全边界

003 的服务端 `contentLevel`、年龄/渠道 gate、SFW fallback、审计和分享降级继续有效，迁移后由 Python policy service/resolver 实现。成人表现不增加任何人物或 Agent 工具权限；默认 SFW，只允许成年虚构角色的非露骨暧昧、亲密和成人幽默。未成年人、强迫/性暴力、图形化性行为、裸露生成、真实人物定向色情或现实伤害计划拒绝并回退 SFW。

## 非目标

- 不实现无限生成地图、后台自主运行的无边界社会或真实世界自动联系。
- 不允许玩家或模型直接命令 A–Y/Z，不把“对质”实现成强制剧情按钮。
- 不把 Pi、DeepSeek、Claude 或其他框架当作世界状态所有者；它们只能通过 Adapter 提交提案。
- 不因迁移而丢失现有单娃娃存档、头像和已确认事实；迁移必须有显式版本和回滚。
- 不声称已完成微信真机、公网部署或模型稳定性，直到对应验收有证据。

## 分阶段迁移目标

1. **M0 契约冻结**：建立 OpenAPI/JSON Schema、角色能力表、事件可见性枚举、回放格式和迁移快照；保留 Node 原型可运行。
2. **M1 Python Kernel 并行**：实现 FastAPI、World Kernel、SQLite event store、确定性 ENV resolver 和无模型 Agent adapters；用合同测试对齐现有 Node 事件。
3. **M2 存档迁移**：把 v5/003 单目标档迁移为 `PLAYER_DOLL`、单成员 target set、房间/关系/记忆事件；完成 CAS、幂等、重放和回滚。
4. **M3 角色交互**：接入 A–Y/Z 注册表、能力校验、隔离上下文和多角色微回合；实现玩家邀请/询问/施压而非直控。
5. **M4 前端切换**：将 `hex/` 改为 TypeScript API client、SSE 事件订阅和事件驱动舞台；保留无模型和离线可玩路径。
6. **M5 模型与策略适配**：接入 Pi/DeepSeek/Claude 等 Provider Adapter，加入超时、预算、取消、策略 gate、审计和 SFW fallback。
7. **M6 发布验证**：桌面移动尺寸、微信 iOS/Android、断网/重连、服务器外访问和回滚分别验收；全部通过前不得删除 Node fallback。
